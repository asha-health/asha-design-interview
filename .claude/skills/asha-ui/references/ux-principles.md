# UX principles

Before you design or change a screen, read the UX principles in `docs/design-system/ux-principles/README.md`. It's
how we think about what goes on a screen: the most frequent jobs get the main surface and the rest stays one click
away, color follows how serious something is, a piece that shows up on several screens is built once and shared,
and so on. Check your design against it the same way you check it against the library. If you break a principle
on purpose, say which one and why.

Sometimes feedback will make you think there's a new principle here, something that should change how many
screens get designed, not just the one in front of you. Don't add it yourself; ask the person driving the chat
first. One-screen fixes and matters of taste don't need a principle.
