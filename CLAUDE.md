# Asha design exercise

This repo is for designing Asha screens as clickable HTML prototypes. There is no backend and no production app:
everything is static HTML and JavaScript with invented data.

- The design system is `docs/design-system/`. `index.html` is the built library (generated by `build.py`; don't edit
  it by hand). `src/kit.js` holds the recipes and components, `src/data.js` the shared invented practice,
  `blocks/*.js` the screens.
- Prototypes live in `prototypes/<name>/`, each with `src/` (edit these), a `build.py` that writes `index.html`, and a
  `serve.py` that serves it and saves picks to `answers.json`. Rebuild after every source edit.
- Before designing, load the `asha-ui` skill and read the UX principles. For a clickable prototype with design
  questions and walkthroughs, use `asha-prototype`; for side-by-side visual options, use
  `asha-design-experimentation`.
- Draw with the library's code; copy classes from the closest block instead of approximating them. When the library
  lacks a piece, check `prototypes/kit-extras.js` (date picker, typed times) before drawing your own.
- Never use real patient data. Invent everything.
- Check your work in a browser before calling it done, and close any browser pages you open.
